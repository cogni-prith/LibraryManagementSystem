> **For agentic workers:** Use superpowers:executing-plans for inline implementation.

**Goal:** Deliver the supplied registration/display assignment as a contained Eclipse Dynamic Web Project.
**Architecture:** HTML posts nine parameters to RegisterServlet; validated values go to a PostgreSQL PreparedStatement. DisplayServlet collects Book rows and forwards to display.jsp. Successful POST redirects with a one-use session message.
**Tech Stack:** Java 8 source, javax Servlet 4.0, JSP, JDBC, PostgreSQL, Tomcat 9, Eclipse WTP.

## Global Constraints

- Required filenames: index.html, RegisterServlet.java, DisplayServlet.java, display.jsp, DBConnection.java, web.xml.
- Preserve the specified BOOK table and nine columns; no automatic schema creation or destructive SQL.
- Single project folder, no framework, no build manager required for Eclipse deployment.
- Database credentials are editable placeholders; PostgreSQL JDBC driver and license are included.

## Review Focus

- Duplicate IDs preserve the original record and show a helpful error.
- Missing/invalid/overflowing numeric input is rejected before insertion.
- Stored HTML is escaped in JSP output.
- Database outage produces a friendly page without exposing connection details.
- Empty table and null optional columns render correctly.
